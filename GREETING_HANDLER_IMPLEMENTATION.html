Response Format

All greeting responses follow the unified API response structure:

Greeting Response Object:
{ "answer": "Hi there! I'm here to help...", "intent_label": "Greeting", "intent_category": "Greeting", "confidence": 1.0, "context": [], "is_greeting": true }

Key characteristics:

  • Intent always labeled "Greeting"
  • Confidence always 1.0 (100%)
  • Context array always empty (no retrieval)
  • is_greeting flag set to true
  • Consistent with support response format

How It Works

Detection Flow

User Query | v [Greeting Handler Check] | +-- greeting? --> Return predefined response | +-- thank you? --> Return predefined response | +-- goodbye? --> Return predefined response | +-- No match --> Proceed to retrieval pipeline | v [Query Classifier] | v [FAISS Retrieval] | v [Response Formatter]

Implementation Details

  • Greeting check occurs before retrieval initialization
  • No FAISS index queries for greeting matches
  • Responses stored in conversation memory
  • Support queries unaffected by greeting handler
  • Response format identical to support queries
  • Easy to extend with new patterns

Code Example

Usage in Chatbot

# In SupportChatbot.answer_query() def answer_query(self, query: str) -> dict: # Check for greeting first greeting_response = self.greeting_handler.get_greeting_response(query) if greeting_response: # Add to memory, return immediately self.memory.add_turn('user', query) self.memory.add_turn('assistant', greeting_response['answer']) return greeting_response # Otherwise, proceed with normal retrieval flow intent = self.classifier.classify(query) retrieved = retrieve(str(query), top_k=self.top_k) # ... rest of support query handling
